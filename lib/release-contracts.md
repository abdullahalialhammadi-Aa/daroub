# Preparation release contracts

Shared types are in toolkit-types.ts. Coordinator owns changes to that file.

- Preparation worker: trip-preparation.ts, fieldbook.ts, new inventory/itinerary UI, preparation exports/tests. Coordinator supplies store functions `loadGear():Promise<GearItem[]>`, `saveGear(item):Promise<GearItem>`, `deleteGear(id):Promise<void>`, `savePreparationBatch(trips,gear):Promise<void>`; existing trip functions preserved. `normalizeTrip(trip)` and `validateGear(input)` will be in preparation-schema.ts (coordinator-owned). Every new trip uses schemaVersion 2, activities/itinerary/suggestionDecisions arrays. Day offset is 0-based. Catalog hooks below available for UI.
- Content worker: catalog-client.tsx and catalog-seed.ts, editor UI/pages, all explorer/report/content reader adaptation. Coordinator supplies GET /api/catalog -> CatalogSnapshot, GET /api/editor -> {role,drafts,history,catalog}; POST /api/editor with {action:'save',draft} or {action:'publish',id,revision,expectedCatalogRevision} or {action:'rollback',revision,expectedCatalogRevision}. Unauthorized reads/writes 403; optimistic mismatch 409; invalid 400. save returns draft, publish/rollback return snapshot. Create own drafts with crypto only inside handlers. Provide client `useCatalog()` -> {catalog,loading,error,refresh}; `CatalogProvider` mounted by root in SiteShell; baseline `seedCatalog` from catalog-seed.ts. Helper functions taking explicit snapshot preferred; do not mutate module-global published data on server.
- Companion worker: packing-engine.ts, assistant UI/endpoint/guide/proposals tests. Coordinator supplies server `readCatalog()` in catalog-server.ts and `loadOwnedTrip(owner,id):Promise<Trip|null>` in sync-server.ts; `loadOwnedGear(owner):Promise<GearItem[]>`. Use request authenticated owner, never client user IDs. Packing engine accepts explicit CatalogSnapshot and trips/gear. Preparation UI can import PackingPanel (new component, props trip,onChange,gear,catalog,locale); coordinate its exact props directly with preparation worker.
- Global CSS, dependency files, translations integration, Site configuration, database, auth, sync, offline shell and shared contracts are coordinator-owned. Workers may create feature copy dictionaries with all five locales and feature CSS files; coordinator integrates imports. Do not edit global styles/dependencies. No Sites tools, no credentials, no recursive agents.
- Concurrency: feature work only in assigned worktree; commit there and report SHA. No merging root. Separate node_modules installed from frozen lockfile; package-lock must remain unchanged. Native-anchor navigation is deliberate.
- Catalog source roles: seedCatalog contains compiled guidance plus rules. All published advice is one versioned snapshot. Fixed terrain IDs remain desert/mountain/forest/coast. Catalog may have more than four destinations; terrainIndex is a category index, never destination array identity. Preserve stable IDs and legacy terrain routing.
- Limits: trip itinerary at most 60 days, 40 entries/day, 600 entries total; checklist 200; suggestions 300; activities 30. Gear quantity 0..10000, names160/notes5000; entry title160/place240/notes2000, duration0..10080 minutes; dayOffset0..3650. Source URL2048 chars, title300. Catalog max100 destinations/300 sources/300 rules, 30 sections/destination and 100 species/destination, body10000 chars/locale; localized names160, summaries2000. Catalog snapshot max 1,500,000 UTF-8 bytes; editor request max 4 MiB UTF-8; sync request max 1 MiB UTF-8; import max 4 MiB and 50 total records per atomic operation. All dates strict calendar YYYY-MM-DD or empty where optional. Text plain, image bundled path or HTTPS approved path, URLs HTTPS only. Source reviewedAt required strict date.
